# SerialProxy —— 串口双向代理（自用学习版）

不需要内核驱动、不需要管理员权限、不需要任何商业组件。
用「com0com 虚拟串口对 + 双向转发」抓取 RS232 设备的真实收发字节，用于逆向/学习老旧设备的通信协议。

安装 com0com 驱动时需要一次管理员授权，之后日常使用始终是普通权限。

---

## 1. 它解决什么问题

老设备没有协议文档，只有一个不好用的上位机。想自己写一个更好的上位机，就必须先知道上位机和设备之间到底发了什么。

Windows 里一个串口同一时刻只能被一个程序打开，所以不能一边让上位机用、一边再抓。
本工具的做法是：

```
                      ┌──────── 本工具 SerialProxy ────────┐
老设备 ──RS232──> COM2 │  左手：COM2（真实，独占设备）        │
（真实串口）            │  右手：COM4（虚拟）                  │
                      └───────────────┬────────────────────┘
                                      │  COM4 ⇠⇢ COM3
                                      │  （com0com 虚拟串口对）
                                      ▼
                               COM3 ── 上位机
```

- **本工具只打开 COM2 和 COM4**，不占用 COM3；
- **上位机改连 COM3**；
- COM3/COM4 只是同一对虚拟口的两端，编号可以换成别的，只要成对且不冲突。

数据流：

| 方向 | 路径 | 工具中的显示 |
| --- | --- | --- |
| 设备 → 上位机 | COM2 → 本工具 → 写 COM4 → 从 COM3 出来 → 上位机 | **输入 RX**（蓝） |
| 上位机 → 设备 | 上位机写 COM3 → 从 COM4 出来 → 本工具 → 写 COM2 → 设备 | **输出 TX**（绿） |

## 2. 前置条件

1. **.NET Framework 4.8**：Windows 10 1809+ / Windows 11 自带，无需安装。
2. **com0com**：创建虚拟串口对，安装驱动需要管理员权限（仅安装时一次）。
   - 程序目录里已经附带官方签名的安装包：`com0com\Setup_com0com_v3.0.0.0_W7_x64_signed.exe`（32 位系统用 `_x86_` 那个）。
   - 直接点主界面右上角的 **环境准备**，按向导安装并创建端口对即可，不用去官网折腾。
   - 如果安装包被误删，向导里也能自动从 SourceForge 下载；下载失败时提供「打开下载页」手动兜底。
3. **真实串口**：主板 RS232、PCIe 串口卡或 USB 转串口都可以。

> com0com 装完如果设备管理器里有黄色感叹号，说明驱动签名/安装有问题。
> 不要在办公/生产机上随意关闭驱动签名强制。

## 3. 使用步骤

1. 设备接好真实串口（例如 COM2）。
2. 首次使用点右上角 **环境准备**：
   - 检测到未安装 → 点「安装 com0com」→ 允许 UAC；
   - 装好后点「重新检测」；
   - 在「创建虚拟串口对」里确认 `COM3 ⇔ COM4`（可改），点「创建端口对」；
   - 关闭对话框回到主界面。
3. 双击 `SerialProxy.exe`（日常使用**不需要管理员权限**）。
4. 设置：
   - 真实串口：`COM2`
   - 虚拟串口：`COM4`
   - 波特率 / 数据位 / 校验 / 停止位 / 流控：**必须与设备和上位机一致**
   - DTR / RTS：按设备要求勾选（多数老设备需要 DTR=true）
5. 上位机里把串口改成 `COM3`，其它参数保持不变。
6. 点击 **▶ 开始**（F5）。
7. 在上位机里操作，观察工具里的：
   - **输入 (RX)**：设备发给上位机的数据
   - **输出 (TX)**：上位机发给设备的数据
8. 需要主动试探设备时，在下方「手动发送」里输入数据（支持 HEX），点发送或按 `Ctrl+Enter`。

## 4. 界面说明

主界面自上而下分五块：标题栏、命令栏、端口栏、抓包工作区、发送栏。

| 区域 | 说明 |
| --- | --- |
| 标题栏 | 运行状态、com0com 检测结果、`环境准备`、`使用说明`（可滚动、可复制全文） |
| 命令栏 | 开始/停止、暂停、清空、导出、详情开关、视图切换（双栏/输入/输出）、格式（HEX+ASCII / HEX / ASCII）、编码（ASCII / GBK / UTF-8）、搜索 |
| 端口栏 | 真实口、虚拟口、串口参数、DTR/RTS、刷新端口 |
| 输入 (RX) | 设备 → PC，蓝色；手动发送的 TX 行会加粗 |
| 输出 (TX) | PC → 设备，绿色 |
| 帧详情 | 选中任意一行，显示完整 HEX dump（偏移 + HEX + ASCII），可一键复制 |
| 手动发送 | 直接写入真实串口发给设备，**不经过上位机**；支持 HEX、追加 CRLF、定时发送、历史记录 |
| 状态栏 | 运行状态、双向字节数、打开日志文件夹 |

### 视图切换

- **双栏**：左输入右输出（默认），中间分隔条可拖动，位置会记住；
- **仅输入** / **仅输出**：把其中一栏折叠，适合窗口窄或只想盯一个方向；
- 用命令栏按钮或 `Ctrl+1 / 2 / 3` 切换；
- 窗口变窄时，格式 / 编码 / 搜索会整体换到第二行，串口参数也会自动折行；窗口太矮时帧详情自动收起，按钮暂时置灰。

### 搜索与暂停

- 搜索框支持 HEX（`01 03`、`0103`）和 ASCII 文本，输入后只显示匹配的帧；按 `Esc` 或点右侧 `×` 清空。
- **暂停**只停止列表刷新，串口照常接收、计数、写 CSV；继续后自动补上暂停期间的记录。
- 每栏最多保留最近 5000 行，导出以 CSV 文件为准。

### 复制 / 导出 / 重发

- 双击某一行 = 复制该行；
- 右键 = 复制选中 / 复制全部可见 / 全选 / 重发选中帧 / 清除这一栏；
- 菜单「文件 → 导出记录」可导出 CSV（Excel 直接打开）或 TXT；
- `F8` 重发上一次手动发送的内容，发送框右侧下拉里有历史记录。

### 快捷键

| 按键 | 功能 |
| --- | --- |
| `F5` | 开始 / 停止代理 |
| `F6` | 暂停 / 恢复列表刷新 |
| `F7` | 显示 / 隐藏帧详情 |
| `F8` | 重发上一次 |
| `Ctrl+F` | 聚焦搜索框 |
| `Ctrl+L` | 清空列表 |
| `Ctrl+E` | 导出 |
| `Ctrl+Enter` | 发送 |
| `Ctrl+1/2/3` | 双栏 / 仅输入 / 仅输出 |

### 文件位置

- 配置：`exe 同目录\serialproxy.ini`，不可写时回退到 `%APPDATA%\SerialProxy\`；
- 日志：默认自动保存 CSV 到 `exe 同目录\logs\`，不可写时回退到 `%LOCALAPPDATA%\SerialProxy\logs\`。

## 5. 协议学习建议

1. **先记参数**：波特率、数据位、校验、停止位、流控、DTR/RTS。
2. **抓最小交互**：让设备空闲，在上位机点一个按钮，记录完整的「命令 + 响应」，注意时间间隔。
3. **找规律**：多次操作对比，找固定头、长度字段、命令字、校验（和/异或/CRC）、结束符。
4. **主动验证**：用手动发送重放命令，每次只改一个字节，观察设备反应。
5. **沉淀命令表**：把每次实验的 CSV 存档，整理成自己的协议表，再写新上位机。

只分析自己的设备、不复制原上位机代码，用于学习和互操作是没问题的。

## 6. 已知限制

| 限制 | 说明 |
| --- | --- |
| 需要上位机能改串口 | 你的场景已满足；若将来遇到写死的软件，可把真实串口改成 COM5，com0com 建 COM2↔COM3，让软件继续用 COM2 |
| 有极小的转发延迟 | 通常几毫秒，老设备基本无感；不要用于对时序极敏感的协议 |
| DTR/RTS 只在启动时设置一次 | Windows 无法读取虚拟口另一端的引脚变化，上位机运行中动态改 DTR/RTS 不会透传到真实串口；若设备依赖硬件流控，请用相同参数直连对照 |
| 手动发送不经过上位机 | 设备会直接回包，上位机可能看到“莫名”的响应；实验时建议先暂停上位机操作 |
| 虚拟口参数 | com0com 虚拟口本身不关心波特率，但本工具与上位机建议设成与设备一致，避免混淆 |
| 日志内存上限 | 界面每栏保留最近 5000 行，内存归档最多 20 万条；完整记录以 CSV 文件为准 |
| 高波特率下的界面刷新 | 长时间跑满 921600 时列表会合并刷新，保证转发线程不被界面拖慢 |

## 7. 常见问题

**打开串口失败：拒绝访问**
- 该端口已被别的程序占用：关掉串口助手、上位机、其他监控工具。
- 确认代理用的是 COM4，上位机用的是 COM3，不要抢同一个口。

**开始代理后上位机收不到数据**
- 确认上位机的端口是 COM3，参数与设备一致。
- 确认设备确实在发数据（看 RX 栏是否有内容）。
- 检查 DTR/RTS 是否需要置位。

**有 RX 没有 TX**
- 上位机可能还没发命令，或它在等设备先发。
- 手动发送可以验证真实串口写方向是否正常。

**上位机打开 COM3 失败**
- com0com 端口对没建成功，打开「环境准备」重新创建一对，或管理员命令行执行 `install PortName=COM3 PortName=COM4`。
- 端口号被其他设备占用，换一对编号。

**环境准备里一直显示“未检测到 com0com”**
- 安装后需要点「重新检测」，或重启一次程序。
- 某些精简系统需要重启后驱动才生效。

**CSV 用 Excel 打开中文乱码**
- 文件是 UTF-8 BOM，正常应可直接打开；若仍乱码，用「数据 → 从文本/CSV」导入并选 UTF-8。

## 8. 构建与分发

需要 .NET Framework 4.8 Developer Pack 或 Visual Studio 2022：

```bat
cd tools\serial-proxy
dotnet build -c Release
```

产物目录：`bin\Release\net48\`

- `SerialProxy.exe`：主程序；
- `com0com\`：官方签名安装包，构建时会自动复制到输出目录。

**分发时把 `SerialProxy.exe` 和 `com0com\` 文件夹一起拷走**即可。
`serialproxy.ini` 和 `logs\` 会在首次运行时自动生成。

## 9. 与主方案的关系

本工具是 `doc/串口监控软件设计方案.md` 中“虚拟串口 + 双向代理”方案的实现：

- 不装内核驱动，因此日常使用**不需要管理员权限**；
- 代价是上位机要改连虚拟串口（你的场景可以改，所以没有代价）。
